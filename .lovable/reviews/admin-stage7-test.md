# 阶段七：管理端实时看板、汇总核算与归档

## 实测范围

2026-11-26，在本地运行的应用中，通过真实超级管理员页面建立独立测试高校，生成高校管理员、上传5位对象与4位评委并开启场次。评委分别使用电脑与iPad尺寸；不模拟手机。

脚本：`tests/e2e/admin_stage7.py`。全部账号密码仅在内存中使用；临时高校通过真实管理页面清理，最后查询确认测试高校残留为0。

## 通过项目

- 空场次显示应到4人、提交0人及完整未提交名单。
- 一位评委通过页面完成表态与确认提交，另外两位通过自身会话的同源原子接口提交；保持结果页打开，禁用实时连接后连续三次自动更新，无需刷新。
- 3张选票、15条明细、6次推荐的预期值、独立明细核算、聚合结果和页面逐人票数一致，剩余未提交1人。
- 展示3份评委确认单；Word文件成功下载；总表打印窗口人数正确。
- 进行中场次不能保存结果存档；结束后存档保存完整总表和3份个人确认单，支持查看/打印。
- 删除弹窗提供密码确认及归档替代提示（本阶段未执行删除及错误密码探针）。
- 场次归档从当前列表移除，对评委查询隐藏；管理员仍能读取全部选票明细。
- 取回后场次仍为已结束，恢复评委可见性；明细与结果存档逐项保持不变，结果页恢复3/4计票。
- 未出现页面运行错误、HTTP错误或504。

## 发现与修复

首页「评审进度看板」打开后不会自动更新：实测三位评委已提交，等待15秒仍显示0。已为原有聚合统计增加前台可见时每10秒刷新，隐藏时暂停；不读取选票明细、不改变权限。相同流程复测，首页自动由0更新为3。

结果页自动更新等待时间分别为约0.003、5.867、3.864秒；计时起点为提交完成后的等待，不代表完整投票响应时长，不能用于计算生产环境P95。
